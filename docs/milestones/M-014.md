# M-014 — Feature-Complete Manual Acceptance Block

**Status:** **INTENDED FUTURE STATE — test/documentation only.**

## Objective

Run and record the existing bounded manual acceptance package against one exact
integrated workspace/component revision set. This block does not implement QoL
features, add battle mechanics, modify Gitlinks, activate Tracker work or
declare a release/freeze by itself.

## Required identity and evidence

Before the run, record sanitized text for the exact workspace, CFRU, DPE and
UPR-FVX SHAs, source configuration, randomizer settings/seed label, emulator
identity and a non-sensitive run label. The current pins are the candidate
target; they must not be substituted for tested SHAs after the fact. The
revision-unbound Gate 1 report must be bound or explicitly left unresolved.

Do not place ROMs, saves, emulator states, builds, binaries, private paths,
secrets, screenshots or raw logs in the repository. A user-run result is
reported as sanitized PASS, FAIL, BLOCKED or N/A with reason.

## Single bounded test scope

Use the 115-case structure prepared in [Workspace Draft PR
#489](https://github.com/Planton361/firered-gen9-randomizer-workspace/pull/489),
refreshed to the exact integrated revisions:

- A: Fresh New Game, Mom/Starter/Rival/Parcel flow and early persistence.
- B: Existing QoL, item, Center/PC, Name Rater and save/reload behavior.
- C: M-009 global frame/lifecycle/menu/warp/battle/Quest Log regression.
- D: One continuous story progression through Hall of Fame.
- E: M-004 renewable-item representatives and controls.
- F: M-008 optional Bill/Sevii behavior and persistence.
- G: Gen-1–9 display, form and crash sanity within the explicit pilot profile.
- H: UPR-FVX output smoke for supported settings, including starter/wild/
  trainer, learnsets/stats/abilities, Pickup Unchanged and clean rejection of
  unsupported Pickup randomization.

The package must preserve the pilot's explicit exclusions and may not turn
unsupported forms or missing battle mechanics into forced test cases.

## Completion boundary

Complete the block only with exact revision identity, no unresolved S0/S1
result, and a sanitized disposition for every mandatory case or approved
profile exclusion. Completion is evidence for the named scope only; it is not a
claim of universal Gen-1–9 compatibility, ROM feature complete, ROM frozen or a
stable support profile without a separately defined release decision.
