## Result and bounded scope

The approved core flow package is integrated. M-001 through M-009 and the
earlier Name Rater rollout remain complete and are not reopened. The historical inventories'
missing-feature lists are superseded by their integration evidence.

Two additional, small source-backed candidates survive this audit:

1. **Premier Ball reward parity:** the enabled CFRU purchase-reward table
   intercepts some ball purchases before the existing Premier Ball path;
   NatDex rewards every ball type with Premier Balls and clamps the reward
   to available bag capacity.
2. **Cinnabar Move Relearner access:** NatDex places the existing mushroom-paid
   service in Cinnabar's Lab Research Room as well as retaining the Two Island
   source object. The integrated CFRU map overlays do not provide that access.

Neither finding justifies a broad QoL port. The first recommendation is a
bounded shop-reward milestone; the second is an optional, separately approved
backlog candidate, not required for pilot feature-complete status unless
explicitly promoted later. Both need later implementation-specific safety
and runtime evidence. No such work was performed here.

This bounded inventory covers the entire requested known set, plus closely
related candidates exposed by the NatDex source and the earlier workspace
inventories. It does not claim an exhaustive comparison of every NatDex UI,
event, audio, graphics, or Pokémon feature.

## Evidence method and classifications

Behavior reference order: **Cyan NatDex source → already approved Faster
FireRed README behavior → pret structure → integrated CFRU source → workspace
acceptance → UPR-FVX where output semantics matter**. Source links below are
immutable pinned revisions. Faster FireRed was read only as its public
[README/product description][F], accessed 2026-09-10; no IPS or other patch
artifact was opened, downloaded or decoded.

The primary reference is not identical to the approved pilot. For example,
NatDex currently consumes TMs, comments out automatic lowercase switching,
and retains random renewable-item sampling. Those are not instructions to
undo the pilot's approved conveniences. A documented deliberate difference
is preserved, rather than counted as missing implementation.

- `ALREADY_IN_CFRU`: present in the pinned engine/configuration; does not by
  itself establish that every player-facing path was runtime-tested.
- `ALREADY_PORTED_M001_M009`: implemented by the named completed milestone.
- `MISSING_SMALL_SOURCE_BACKED_QOL`: concrete absent behavior with an existing,
  bounded target integration approach; estimate, not implementation acceptance.
- `PRESERVE_ONLY`: existing capability or intentional policy difference; no port.
- `NOT_RELEVANT_TO_PILOT`: outside this pilot's QoL scope.
- `TOO_DEEP_FOR_PILOT`: disproportionate to this bounded parity package.
- `UNKNOWN`: insufficient target integration or product-policy evidence to
  recommend a port. It is not counted as an implementation requirement.

In the matrices, **C** means pinned CFRU source/configuration and **N** means
pinned Cyan NatDex. “Project” adds accepted scope and evidence, not an assumed
ROM result. Practical-detail tables are joined to behavior tables by ID and
together provide all required fields for each candidate. Risk estimates refer
to changing the behavior, not to a newly discovered runtime failure.

## G1 — recommended next minimal milestone: Premier Ball parity

**INTENDED FUTURE STATE:** Remaining source-backed implementation candidate:
**M-013 — NatDex Premier Ball purchase bonus**. This closure records the
candidate; its implementation has not started.

The concrete counterexample is a purchase of 10 Great Balls with space for
the reward. N's `Task_ReturnToItemListAfterItemPurchase` gives one Premier
Ball. C's enabled custom table gives one Dusk Ball and returns before the
Premier branch. Buying 10 Ultra Balls similarly yields a Luxury Ball. Buying
20 ordinary Poké Balls already yields two Premier Balls: this is a partial
parity correction, not a new multi-ball feature. Sources: [N-shop], [C-item],
[C-config].

N also explicitly limits Premier quantity to remaining bag capacity. C asks
`AddBagItem` for the entire computed reward and contains no explicit partial
