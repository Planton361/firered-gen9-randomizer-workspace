## Fully specified candidate policies

The acquisition target is Showdown move key `lowkick`, mapped to existing `MOVE_LOWKICK`. The generation being selected here is **acquisition generation**, independently of the previously approved level-up dataset selection. No level-up evidence is used to add machine compatibility.

**Policy A — selected Gen-9 machine membership:** select generation **9**, method **M**. A local constant is positive only if the reviewed resolver finds a literal `9M...` Low Kick source on its exact source identity or accepted acquisition ancestor/owner. There is no fallback to Gen 8 when Gen-9 M evidence is absent. This is the specified Gen-9 method policy on the pinned aggregate Showdown data, not an SV TM-order, game-availability or cartridge-legality claim. Represented Mega/GMax/battle forms may inherit their accepted parent’s `9M`; their own older level-up dataset does not turn that machine evidence into `8M` or block an accepted acquisition parent.

**Policy B — historical machine-method union:** select generations **1–9**, method **M**, using the same resolver. Union only literal machine tokens found through accepted identities/ancestors/owners. The pinned data actually has Low Kick M evidence only in generations **8 and 9**. Historical tutor (`T`), level-up (`L`), egg (`E`), event (`S`) and other methods never qualify. This is a new candidate TM aggregation policy, not a revival of the obsolete per-move historical-union level-up policy.

For both, the resolver is:

1. Restrict ordinary mapped source identities to NatDex 1–1025; use unchanged `resolve_species`, reviewed aliases and exact existing DPE/CFRU constants. Blocked/ignored source forms never obtain a new mapping by name similarity.
2. Read literal Low Kick `[1-9]M...` tokens. Reuse #616 `acquisition_evidence`: recursively inherit `prevo` when specified; otherwise, only when the exact key has **no learnset record at all**, follow `changesFrom`, then `battleOnly`, then `baseSpecies`. An existing learnset record lacking Low Kick does not alone authorize base-form inheritance. Cycles fail closed. Pre-evolution M inheritance is the accepted acquisition traversal, not the different level-up no-prevo rule.
3. Preserve provenance paths and assert token equality with the unchanged helper for every traversed identity. The helper's top-level string metadata does not parse battle-parent arrays; separately verify all three array cases against every explicit parent. Zygarde-Complete, future Zygarde-Mega and Necrozma-Ultra have unanimous **empty** Low Kick M sets, matching the helper. No ambiguous array result is silently treated as negative.
4. Add only the enumerated nonexcluded local ownership groups. Verify existing CFRU/DPE learnset pointers and require Low Kick M-token equivalence for listed equivalent sources independently; matching level-up data alone is insufficient. For this move, only the three Ogerpon mask constants add positives. The ownership file is learnset-only evidence: its reuse here is explicit in both **candidate** policies, not an approved general TM policy or base/Ability/mechanics waiver. Splits and Zarude-Dada are already exact/alias-mapped; they acquire no prefix-based parent rule.
5. Require all identities writing one local row to agree on M tokens, and require unique numeric DPE row identities. Explicitly excluded custom/noncombat/sentinel constants never gain membership from shared pointers. Every named local constant is accounted for: **1,404 eligible rows + 11 excluded = 1,415**. Reserved unnamed rows stay outside the species manifest.
6. **Only after this complete resolver and chosen generation/method filter**, a nonpositive eligible row is `POLICY_NEGATIVE` under that candidate's closed manifest: A 1,192; B 1,150. This is absence from the specified pinned-reference candidate, not a claim that the species cannot learn Low Kick by any method, in any game, or under every possible project policy. Excluded/unrepresentable identities are not counted as certified negatives. No negative is inherited from the old Hail/tutor file.

## Existing representation and change boundary
